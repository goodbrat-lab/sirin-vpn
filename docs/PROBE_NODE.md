## 2. Базовая безопасность и Hardening

Узел настроен в соответствии с требованиями изолированного публичного узла:

1. **SSH:**
   - Вход строго по открытым SSH-ключам (Ed25519).
   - Вход по паролю отключён: `/etc/ssh/sshd_config.d/99-sirin-hardening.conf`
     ```text
     PasswordAuthentication no
     PermitRootLogin prohibit-password
     PubkeyAuthentication yes
     ```
2. **Брандмауэр (`ufw`):**
   - Политика по умолчанию: `default deny incoming`, `default allow outgoing`.
   - Разрешён только порт `22/tcp`.
3. **Автоматическая защита:**
   - **`fail2ban`**: активен, отслеживает SSH-атаки по словарю.
   - **`unattended-upgrades`**: активен, автоматически устанавливает критические обновления безопасности ОС.

## 3. Мониторинг доступности из РФ (`scripts/monitor_availability.sh`)

Скрипт развёрнут по пути `/usr/local/bin/monitor_availability.sh` и настроен на непрерывный синтетический мониторинг двух ключевых плоскостей:

1. **VPN Egress:** `94.183.159.114:443` (TCP SYN connect и HTTPS health).
2. **API Control Plane:** `https://crp.guseynovia.ru/health` (HTTP GET /health, код 200).

### Логика алертинга
- **Интервал опроса:** каждые 5 минут (`/etc/cron.d/sirin-probe`).
- **Порог срабатывания:** 3 последовательные ошибки соединения подряд.
- **Действие при аварии:** отправка структурированного алерта в Telegram (через выделенного probe-бота).
- **Восстановление:** при возобновлении связи после серии ошибок скрипт автоматически отсылает уведомление `✅ Доступность восстановлена` и сбрасывает счётчик.
- **Логирование:** `/var/log/sirin-probe.log` (фиксирует timestamp, target, endpoint, code, latency_ms, streak).
- **Ротация логов:** `/etc/logrotate.d/sirin-probe` (ежедневно, хранение 7 архивов).

### Конфигурация секретов
Файл конфигурации: `/etc/sirin-probe/config.env` (права `chmod 600`):
```bash
TG_BOT_TOKEN=REPLACE_WITH_PROBE_BOT_TOKEN
TG_CHAT_ID=1191978271
VPN_HOST=94.183.159.114
VPN_PORT=443
API_URL=https://crp.guseynovia.ru/health
TIMEOUT_SEC=5
FAIL_THRESHOLD=3
LOG_FILE=/var/log/sirin-probe.log
```

> [!IMPORTANT]
> Для отправки алертов в Telegram используется отдельный probe-бот, не связанный с продуктивным ботом `@sirin_crp_bot`.

## 4. Сетевое качество до европейского узла (NL Egress: 94.183.159.114)

Углублённая диагностика качества прямого сетевого стыка Москва (AS33842) → Нидерланды (`94.183.159.114`):

- **ICMP Ping (300 пакетов, серии по 100 с интервалом 0.2 с):**
  - Потери пакетов: **0.0%** (300/300 получено)
  - Минимальная задержка: **38.01 мс**
  - Средняя задержка (RTT avg): **38.94 мс**
  - Максимальная задержка: **48.63 мс**
  - Джиттер (mdev): **~1.13 мс**
- **Трассировка (MTR 100 циклов):**
  - Потери на магистральных хопах (Ростелеком AS12389, GTT Amsterdam AS3257): **0.0%**.
  - На целевом хосте: 1% (99/100 принято, avg 38.9 мс).
- **Синтетический мониторинг (48 часов):**
  - 1 058 пятиминутных проверок доступности: **0 спонтанных сбоев** (100% доступность).
- **Пропускная способность:**
  - ~20–25 Мбит/с устойчивого скачивания на тарифе VPS. Порт 5201 на `94.183.159.114` закрыт облачным фаерволом в рамках OpSec.

Первоначальные 5% потерь при первичной настройке были разовым артефактом инициализации VM. Канал признан эталонно стабильным.

## 5. Роль Relay 1 (Фаза B, развёрнут)

Для реализации каскада «Невидимая вуаль»:
- Установлен и настроен **`nginx`** с модулем **`libnginx-mod-stream`** (`/etc/nginx/streams-available/sirin-relay1.conf`).
- Реализован прозрачный **TLS-passthrough** (stream forward) трафика с порта `443/tcp` релея на `94.183.159.114:443` без терминации TLS и без доступа к приватным ключам пользователей.
- В брандмауэре `ufw` открыт порт `443/tcp`. Внешнее TCP-подключение успешно верифицировано.
- Подробная спецификация, конфигурация и результаты тестов приведены в [RELAY_1.md](RELAY_1.md).

## 6. OpSec (Операционная безопасность)

На данном узле **СТРОГО ЗАПРЕЩЕНО** размещать:
- `clients.json`, списки пользователей, персональные данные.
- Клиентские и серверные UUID, Xray/VLESS Reality приватные ключи.
- Панель управления и API-токены администратора.
- Токен продуктивного Telegram-бота (`@sirin_crp_bot`).

RU VPS рассматривается как полностью публичный расходник («honeypot / probe»), компрометация которого не наносит ущерба приватности пользователей Sirin VPN.
