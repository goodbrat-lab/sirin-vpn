# Архитектура безопасности Sirin: Цепочка доверия обновлений

В клиенте Sirin Android (начиная с версии `v1.3.2`) реализована эшелонированная трёхуровневая модель верификации обновлений (Defense-in-Depth). Модель гарантирует невозможность внедрения вредоносного кода через механизм автообновления даже при компрометации учётной записи или инфраструктуры GitHub Releases.

---

## 1. Модель угроз и риски

В стандартных схемах обновления приложений с открытым исходным кодом распространены уязвимости:
1. **Подмена бинарного файла на GitHub Releases**:
   - При утечке персонального токена разработчика (PAT), взломе CI/CD-пайплайна или атаке на хостинг релизов злоумышленник может заменить APK и файл `checksums.txt`.
   - Если проверка полагается только на `checksums.txt`, клиент скачает валидный для себя хэш и запустит установку трояна.
2. **MitM-перехват незащищённого трафика**:
   - Модификация трафика в процессе загрузки или передача битых/усечённых данных.
3. **Подмена пакета сторонним сертификатом**:
   - Попытка подсунуть APK, подписанный посторонним ключом разработчика.

## 2. Архитектура трёхзвенной цепочки доверия

```
┌────────────────────────────────────────────────────────┐
│             Вшитый ключ автора (APK)                   │
│         sirin_pubkey.asc (RSA 4096-bit)                │
└──────────────────────────┬─────────────────────────────┘
                           │ 1. Проверка GPG-подписи
                           ▼
┌────────────────────────────────────────────────────────┐
│             Файл checksums.txt.asc                     │
│         (Отсоединённая сигнатура OpenPGP)              │
├────────────────────────────────────────────────────────┤
│                 checksums.txt                          │
│         (Канонические SHA-256 хэши APK)                │
└──────────────────────────┬─────────────────────────────┘
                           │ 2. Проверка SHA-256
                           ▼
┌────────────────────────────────────────────────────────┐
│             Скачанный sirin-*.apk                      │
└──────────────────────────┬─────────────────────────────┘
                           │ 3. Сверка сертификата Keystore
                           ▼
┌────────────────────────────────────────────────────────┐
│          Android Package Manager / OS Trust            │
│   (Сертификат APK == Сертификат установленного пакета) │
└────────────────────────────────────────────────────────┘
```

### Уровень 1: Криптографическая подпись OpenPGP (GPG)
- **Публичный ключ**: Вшит напрямую в ресурсы APK (`apps/android/app/src/main/res/raw/sirin_pubkey.asc`).
  - Key ID: `5D79136BFC6A5108` (RSA 4096 bit).
  - Отпечаток: `CAC8 1FBB 1D14 52E4 5DDF A4DC 5D79 136B FC6A 5108`.
- **Приватный ключ**: Хранится изолированно в защищённых секретах CI (`GPG_PRIVATE_KEY`, `GPG_PASSPHRASE`) и защищён кодовой фразой. Не публикуется в исходном коде.
- **Процесс**: 
  - CI генерирует файл `checksums.txt` и подписывает его:
    ```bash
    gpg --batch --yes --pinentry-mode loopback --detach-sign --armor checksums.txt -> checksums.txt.asc
    ```
  - `UpdateChecker.kt` через библиотеку BouncyCastle (`bcpg-jdk18on`, `bcprov-jdk18on`, `bcutil-jdk18on`) валидирует подпись `checksums.txt.asc` строго по вшитому публичному ключу.
  - Если подпись отсутствует, повреждена или сформирована другим ключом, процесс немедленно прерывается, скачанный файл удаляется.

### Уровень 2: Хэширование целостности (SHA-256)
- После подтверждения подлинности `checksums.txt` из него извлекается эталонный хэш SHA-256 для целевого файла APK.
- Клиент локально вычисляет хэш скачанного файла и сравнивает его с эталонным.
- Исключается установка неполных, повреждённых или подменённых файлов в процессе передачи по сети.

### Уровень 3: Защита целостности экосистемы Android (Keystore Certificate Pinning)
- Перед передачей APK в системный `PackageInstaller` клиент с помощью `PackageManager.getPackageArchiveInfo` извлекает байты сертификата подписи из скачанного APK.
- Сертификат побайтово сравнивается с сертификатом запущенного приложения:
  ```kotlin
  val matches = currentSignatures.any { curSig ->
      archiveSignatures.any { newSig -> curSig.contentEquals(newSig) }
  }
  ```
- Даже если злоумышленник завладел бы инфраструктурой GitHub, подменить APK на сборку со своим ключом невозможно: приложение и сама операционная система Android откажут в установке пакета (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`).

---

## 3. Итог матрицы защищённости

| Вектор атаки | Уровень защиты | Результат |
|---|---|---|
| Компрометация токена GitHub Releases | Уровень 1 (GPG) | Поддельный `checksums.txt` будет отклонён; APK удалится |
| Атака типа Man-in-the-Middle (MitM) | Уровень 1 + 2 | Нарушение подписи или хэша; установка блокируется |
| Повреждение файла при скачивании | Уровень 2 (SHA-256) | Несовпадение контрольной суммы; немедленное удаление |
| Попытка обновления APK с чужим Keystore | Уровень 3 (Package Manager) | Отклонение клиентом + блокировка на уровне ОС Android |
