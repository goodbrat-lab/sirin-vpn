## 2. Результаты углублённой сетевой диагностики

### 2.1. Контекст проверки
При первичной инициализации узла 22 октября был зафиксирован разовый показатель потерь ICMP-пакетов (~5%) до нидерландского узла выгрузки (`94.183.159.114`). Для релея входящего клиентского каскада такие потери недопустимы. Было проведено детальное многофакторное исследование стабильности маршрута и канала.

### 2.2. Расширенное тестирование потерь и джиттера (ICMP Ping)
Выполнено 3 серии по 100 пакетов с коротким интервалом 0.2 с до NL-выхода (`94.183.159.114`):

|---|---|---|---|---|---|---|
| **Серия 1 (100 пакетов)** | 100 / 100 | **0.0%** | 38.007 мс | 38.859 мс | 42.005 мс | 0.847 мс |
| **Серия 2 (100 пакетов)** | 100 / 100 | **0.0%** | 38.025 мс | 39.108 мс | 48.625 мс | 1.526 мс |
| **Серия 3 (100 пакетов)** | 100 / 100 | **0.0%** | 38.021 мс | 38.850 мс | 44.477 мс | 1.024 мс |
| **ИТОГО (300 пакетов)** | **300 / 300** | **0.0%** | **38.007 мс** | **38.940 мс** | **48.625 мс** | **~1.13 мс** |

**Вывод:** Потери пакетов на магистрали полностью отсутствуют. Среднее время кругового обращения (RTT) составляет стабильные **~38.9 мс** при джиттере порядка **1.1 мс**, что идеально подходит для туннелирования интерактивного трафика и мультимедиа.

### 2.3. Анализ трассировки маршрута (MTR 100 циклов)
Диагностика с помощью `mtr -rwzc 100 94.183.159.114`:
- **Хост 1 (`_gateway`, AS33842):** фиксируется ~6% потерь пакетов. Это стандартный ICMP rate-limiting на control-plane гипервизора Citytelecom. На сквозной транзитный трафик он не влияет.
- **Хосты 2–6 (Магистраль Citytelecom / Ростелеком AS12389):** 0.0% потерь.
- **Хосты 7–9 (Трансъевропейский стык GTT Amsterdam AS3257):** 0.0% потерь.
- **Хост 10 (Целевой узел 94.183.159.114):** 1% потерь (99/100 принято), средний RTT 38.9 мс, StDev 0.9 мс.

### 2.4. Сравнительный бенчмарк независимых направлений
Тестовые замеры пинга до независимых узлов подтверждают эталонную стабильность сетевого стека VPS:
- **Яндекс (Москва, `77.88.8.8`):** RTT avg = 12.38 мс, mdev = 0.38 мс (100% стабильность).
- **Google Public DNS (`8.8.8.8`):** RTT avg = 12.72 мс, mdev = 0.23 мс.
- **Quad9 EU (`9.9.9.9`):** RTT avg = 33.30 мс, mdev = 0.35 мс.
- **Cloudflare EU (`1.1.1.1`):** RTT avg = 39.57 мс, mdev = 1.04 мс.

### 2.5. Исторический аудит синтетического мониторинга (48 часов)
В логе `/var/log/sirin-probe.log` probe-ноды проанализировано **1 058 непрерывных циклов** проверки доступности (каждые 5 минут):
- Спонтанных сбоев соединения до NL VPN Egress: **0** (доступность 100.0%).
- Единственные 4 зафиксированных сбоя были вызваны запланированным стресс-тестом эмуляции блокировки через `iptables -j DROP` 22 октября.

### 2.6. Оценка пропускной способности
- По соображениям операционной безопасности (OpSec) и брандмауэра облачного провайдера на сервере в Нидерландах открыты строго рабочие порты (`22`, `80`, `443`, `8443`, `56005`). Порт `5201` (`iperf3`) закрыт внешним файрволом провайдера.
- Реальная скорость скачивания с релея замерена через прямые HTTP-потоки и составляет **~20–25 Мбит/с**, что гарантирует запас полосы для тестовой группы из 8–10 пользователей.

### 2.7. Итоговый вердикт
Первоначальные 5% потерь являлись кратковременным артефактом начальной инициализации виртуальной машины и фонового обновления пакетов ОС. Сетевой канал признан **полностью пригодным** для эксплуатации в качестве входного узла Relay 1.

## 3. Архитектура и настройка Relay 1 (TLS Passthrough)

### 3.1. Принцип работы (Zero-Decryption / Zero-Knowledge)
Входной релей **не расшифровывает** пользовательские соединения. Используется чистый TCP stream proxy поверх `nginx` (`libnginx-mod-stream`):
1. Клиент подключается к российскому IP `185.182.65.219:443`.
2. ТСПУ видит обычную зашифрованную TLS-сессию к российскому серверу с доверенным SNI (например, `sun8-21.userapi.com` или `wildberries.ru`). Трансграничной аномалии для ТСПУ нет.
3. Nginx пересылает «сырые» зашифрованные TCP-пакеты на зарубежный сервер выгрузки `94.183.159.114:443`.
4. Рукопожатие VLESS Reality и расшифровка происходят исключительно на целевом нидерландском сервере.

```
[ Клиент Sirin ]
       │
       ▼ (Внутрироссийский TLS 443, SNI: userapi.com / wildberries.ru)
[ RU Relay 1: 185.182.65.219:443 ]
       │  (Nginx stream proxy_pass без расшифровки)
       ▼ (Трансграничный TCP forward)
[ NL Egress: 94.183.159.114:443 ]
       │  (Терминация VLESS Reality, Xray Core)
       ▼
 [ Интернет ]
```

### 3.2. Конфигурация Nginx
Файл `/etc/nginx/streams-available/sirin-relay1.conf`:
```nginx
upstream sirin_nl_egress {
    server 94.183.159.114:443;
}

server {
    listen 443;
    listen [::]:443;
    proxy_pass sirin_nl_egress;
    proxy_connect_timeout 5s;
    proxy_timeout 1h;
}
```

Активация в `/etc/nginx/nginx.conf`:
```nginx
stream {
    include /etc/nginx/streams-enabled/*.conf;
}
```

Симлинк:
```bash
ln -s /etc/nginx/streams-available/sirin-relay1.conf /etc/nginx/streams-enabled/
nginx -t && systemctl reload nginx
```

### 3.3. Брандмауэр (`ufw`)
Открыт порт 443 для приёма клиентского трафика:
```bash
ufw allow 443/tcp
ufw status verbose
```
Статус:
- `22/tcp`: ALLOW IN
- `443/tcp`: ALLOW IN

Внешняя верификация: порт `443/tcp` успешно отвечает на TCP SYN рукопожатия и ретранслирует сессии.

## 4. OpSec (Операционная безопасность)

Узел Relay 1 подчиняется строгим правилам изоляции:
1. **Никаких ключей и баз:** на RU VPS отсутствуют `clients.json`, UUID, приватные ключи Xray Reality, база данных и токены администратора.
2. **Никакой терминации криптографии:** трафик проходит сквозь Nginx в неизменном зашифрованном виде.
3. **Расходный статус:** при блокировке IP-адреса узла ТСПУ инфраструктура не страдает — клиенты моментально переключаются на прямой NL-выход или другой релей через обновление параметров в `sirinapi`.
