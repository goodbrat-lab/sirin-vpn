# Чек-лист ручной приёмки Android-клиента Sirin (P0 верификация)

Данный документ содержит пошаговый регламент верификации критических механизмов безопасности Android-клиента Sirin VPN (версия `android-v1.3.2+`). Регламент применяется для приёмочного тестирования на физических устройствах или эмуляторах Android (API 26–35+).

---

## 1. Тест Kill Switch (Блокировка трафика при обрыве туннеля)

### Цель
Убедиться, что при неожиданном обрыве связи или падении VPN-сессии трафик незащищённых приложений полностью блокируется («чёрная дыра»), исключая утечку реального IP-адреса пользователя в открытую сеть оператора.

### Предусловия
- Установлен APK `sirin-debug.apk` / `sirin-release.apk` (v1.3.2+).
- В настройках приложения включён переключатель **Kill Switch** (Блокировка при обрыве).

### Шаги проверки
1. Открыть Sirin VPN и нажать кнопку подключения. Дождаться перехода в статус **«Подключено»**.
2. В браузере или терминале (`adb shell curl -m 3 https://ifconfig.me`) убедиться, что отображается IP-адрес VPN-сервера.
3. Сымитировать внезапный разрыв туннеля:
   - *Вариант А (серверный)*: на сервере временно выполнить `iptables -I INPUT -s <IP_клиента> -j DROP`.
   - *Вариант Б (клиентский)*: в терминале устройства выполнить `kill -9` процесса движка или кратковременно разорвать маршрут к серверу.
4. Выполнить сетевой запрос из любого браузера или выполнить:
   ```bash
   adb shell curl -m 4 https://ifconfig.me
   ```
5. Проверить системные уведомления и лог приложения:
   - В логе должна появиться запись: `Kill Switch сработал: интернет заблокирован, пока туннель не восстановится`.

### Ожидаемый результат
- Запрос завершается с ошибкой таймаута (`Connection timed out` или `Network unreachable`).
- Реальный IP-адрес провайдера/сотового оператора **не раскрывается**.
- Трафик не уходит через физический сетевой интерфейс в обход VPN.

## 2. Тест совместимости Kill Switch и Split Tunneling (BYPASS)

### Цель
Проверить отсутствие регрессии раздельного туннелирования при активном Kill Switch: приложения из списка исключений (BYPASS) должны продолжать работать напрямую через сеть оператора даже во время обрыва VPN.

### Предусловия
- В разделе «Раздельное туннелирование» выбран режим **BYPASS** (Исключить приложения).
- В список исключений добавлено тестовое приложение (например, `curl`, браузер Chrome или банковское приложение).
- Включён **Kill Switch**.

### Шаги проверки
1. Подключиться к Sirin VPN.
2. Проверить доступность сети из исключённого приложения: трафик должен идти через IP локального провайдера (WAN).
3. Сымитировать разрыв туннеля VPN (срабатывание заглушки Kill Switch).
4. Проверить доступ в интернет:
   - Из обычного приложения (не в списке BYPASS) — сеть заблокирована (таймаут).
   - Из исключённого приложения (в списке BYPASS) — сайты открываются через прямое соединение оператора.

### Ожидаемый результат
- Заглушка Kill Switch изолирует только тот трафик, который обязан защищаться туннелем.
- Исключённые сервисы не теряют доступ к интернету из-за падения VPN.

## 3. Тест защиты от утечки IPv6 (IPv6 Leak Protection)

### Цель
Подтвердить, что трафик по протоколу IPv6 не уходит в сеть оператора в обход VPN-туннеля.

### Предусловия
- Устройство подключено к мобильной сети LTE/5G или Wi-Fi с поддержкой IPv6.
- Sirin VPN подключён.

### Шаги проверки
1. Открыть сайт тестирования IPv6 (например, [test-ipv6.com](https://test-ipv6.com) или [ipleak.net](https://ipleak.net)).
2. Запустить полный тест утечек.
3. Проверить через `adb shell`:
   ```bash
   adb shell ip -6 route show
   ```

### Ожидаемый результат
- Сайт сообщает либо:
  - «IPv6 не обнаружен» (адрес `fd00::1/128` перехватывает маршрут по умолчанию `::/0`), либо
  - Весь IPv6-трафик завершается внутри защищённого интерфейса без передачи в WAN.
- Реальный публичный IPv6-адрес устройства не отображается в отчёте теста.

## 4. Тест трёхзвенной цепочки доверия при обновлении (Update Chain)

### Цель
Убедиться, что механизм `UpdateChecker` блокирует установку скомпрометированных обновлений при любых манипуляциях с файлами релиза.

### Сценарий 4.1: Валидный релиз
1. Нажать «Проверить обновления» в настройках.
2. Скачиваются `checksums.txt`, `checksums.txt.asc` и APK.
3. GPG-подпись совпадает с вшитым ключом `sirin_pubkey.asc`, хэш SHA-256 совпадает, сертификат APK идентичен установленному.
4. **Результат:** Запускается системный диалог обновления приложения.

### Сценарий 4.2: Поддельный или неподписанный `checksums.txt`
1. Злоумышленник заменил APK и пересчитал `checksums.txt`, но не имеет приватного GPG-ключа автора.
2. `UpdateChecker` загружает файлы и производит верификацию сигнатуры OpenPGP.
3. **Результат:** 
   - Выводится сообщение: *«Ошибка безопасности: GPG-подпись checksums.txt недействительна (возможна подмена файлов релиза)»*.
   - Скачанный APK немедленно удаляется из файловой системы устройства (`targetFile.delete()`).
   - Установка блокируется.

### Сценарий 4.3: Поддельный сертификат APK (чужой Keystore)
1. APK собран и подписан сторонним debug/release ключом.
2. `UpdateChecker` проверяет подпись через `PackageManager`.
3. **Результат:** 
   - Выводится сообщение: *«Ошибка безопасности: сертификат подписи скачанного APK не совпадает с установленным приложением»*.
   - APK удаляется, установка отменяется.
