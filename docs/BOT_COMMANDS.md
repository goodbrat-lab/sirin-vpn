# Управление и команды Telegram-бота Sirin (@sirin_crp_bot)

Telegram-бот Sirin предназначен для выдачи и оперативного управления ключами доступа (клиентами) в протоколе Sirin VPN.

---

## 1. Основной интерфейс: Интерактивное меню

Основным пользовательским интерфейсом (UX) бота является **интерактивное меню с inline-кнопками и пошаговыми FSM-диалогами**. Все операции (создание, просмотр, продление, переименование, удаление) выполняются в едином диалоговом окне без необходимости ручного набора команд.

Подробная схема навигации и экранов представлена в документе [BOT_UX_MAP.md](BOT_UX_MAP.md).

### Главный экран (`/menu` или `/start`):
```text
👋 Sirin Bot — панель управления

Клиентов: 12 · Активных: 8 · Просрочено: 1
```
Кнопки навигации:
- `[👥 Клиенты]` — постраничный список клиентов (по 5 на страницу) с цветовой индикацией статуса и кнопками карточек.
- `[➕ Новый клиент]` — пошаговый мастер создания ключа (Шаг 1: Имя → Шаг 2: Выбор срока → Шаг 3: Подтверждение).
- `[📊 Статистика]` — сводные метрики и быстрый фильтр истекающих ключей (`[⏳ Истекают <7д]`).
- `[🔍 Поиск]` — быстрый поиск клиента по имени или префиксу UUID.
- `[⚙️ Настройки]` — просмотр администраторов и безопасная очистка просроченных ключей с подтверждением.
- `[ℹ️ Помощь]` — встроенная справка по боту.

---

## 2. Команды быстрого доступа (Обратная совместимость)

Для опытных администраторов и автоматизации сохранены классические текстовые команды. Они работают как прямые алиасы соответствующих экранов и действий:

| Команда | Описание | Синтаксис |
| :--- | :--- | :--- |
| `/menu` | Главное интерактивное меню | `/menu` |
| `/newkey` | Создание ключа (без аргументов открывает мастер) | `/newkey [имя] [дни]` |
| `/list` | Постраничный список клиентов с фильтром | `/list [фильтр]` |
| `/info` | Полная карточка клиента с кнопками управления | `/info <имя \| uuid>` |
| `/find` | Быстрый поиск клиента по имени или UUID | `/find <запрос>` |
| `/rename` | Переименование клиента | `/rename <старое_имя \| uuid> -> <новое_имя>` |
| `/extend` | Продление срока действия ключа | `/extend <имя \| uuid> <дни>` |
| `/shorten` | Сокращение срока действия ключа | `/shorten <имя \| uuid> <дни>` |
| `/disable` | Отключение клиента (soft-delete, `revoked=true`) | `/disable <имя \| uuid>` |
| `/enable` | Повторная активация клиента (`revoked=false`) | `/enable <имя \| uuid>` |
| `/delete` | Полное удаление клиента из базы данных | `/delete <имя \| uuid> [--force]` |
| `/status` | Статистика сервера и клиентов | `/status` |

---

## 2. Подробное описание и примеры команд

### 2.1 `/newkey <имя> [дни]`
Создаёт нового клиента в `clients.json`.
- **Имя**: допускает многословные строки (например, «Иван Петров»). Пробелы схлопываются, длина ограничена 64 символами.
- **Дни** (опционально): срок действия ключа в днях (от 1 до 3650). По умолчанию: 30 дней. Значения выше 3650 ограничиваются 3650 днями.
- **Безопасность**: UUID ключа в сообщении маскируется (первые 8 символов + `…`). Полный UUID передаётся по нажатию inline-кнопки «Показать».

**Примеры:**
```text
/newkey Марина Иванова 365
/newkey Офис Тестовый Ноутбук 7
/newkey Алексей
```

---

### 2.2 `/list [фильтр]`
Выводит список клиентов с пагинацией (по 10 записей на страницу) и итоговой статистикой (всего, активных, отключённых, просроченных).
- К каждому клиенту отображается статус-эмодзи:
  - 🟢 — активен
  - 🔴 — отключён (`revoked=true`)
  - ⏳ — просрочен
- Указывается оставшийся срок действия (`14д`, `истекает сегодня`, `просрочен 3д`, `бессрочно`).
- Доступны inline-кнопки навигации: «⬅️ Назад», «Вперёд ➡️», «🔄 Обновить».

**Примеры:**
```text
/list
/list Марина
```

---

### 2.3 `/info <имя | uuid>`
Открывает подробную карточку клиента с кнопками интерактивного управления.
- Поиск клиента производится по точному имени, префиксу UUID (от 6 символов) или вхождению подстроки.
- Отображаются: имя, маскированный UUID, статус, дата создания, дата окончания, оставшийся срок.
- Inline-кнопки:
  - `👁 Показать UUID`
  - `➕ Продлить (+30д)`
  - `⏸ Отключить` / `▶️ Включить`
  - `✏️ Переименовать`
  - `🗑 Удалить`

**Примеры:**
```text
/info Марина Иванова
/info a1b2c3d4
```

---

### 2.4 `/find <запрос>`
Быстрый поиск клиента. Если найдено точное совпадение — сразу открывает карточку `/info`. Если найдено несколько клиентов — открывает страницу `/list` с фильтром по данному запросу.

**Примеры:**
```text
/find Иванова
```

---

### 2.5 `/rename <старое_имя | uuid> -> <новое_имя>`
Переименовывает клиента в `clients.json` без смены UUID и ключей шифрования. Разделитель — стрелка `->`.

**Примеры:**
```text
/rename Марина Иванова -> Марина И.
/rename a1b2c3d4 -> Сервер Бэкапов
```

---

### 2.6 `/extend <имя | uuid> <дни>` и `/shorten <имя | uuid> <дни>`
Продлевает или уменьшает срок действия ключа на указанное количество дней.
- Если клиент был просрочен, продление отсчитывается от текущего момента.
- При сокращении срока дата не сдвигается в прошлое дальше текущего момента.

**Примеры:**
```text
/extend Марина 30
/shorten Марина 10
```

---

### 2.7 `/disable <имя | uuid>` и `/enable <имя | uuid>`
- `/disable`: устанавливает `revoked = true`. Клиент мгновенно теряет доступ (демон `sirind` синхронизирует статус в течение 30 секунд). Ключ не удаляется из истории.
- `/enable`: возвращает `revoked = false`, восстанавливая доступ (если срок действия не истёк).

**Примеры:**
```text
/disable Марина
/enable Марина
```

---

### 2.8 `/delete <имя | uuid> [--force]`
Удаляет клиента из базы данных `clients.json`.
- Без флага `--force` бот выводит предупреждение с кнопками подтверждения:
  - `⚠️ Да, удалить`
  - `❌ Отмена`
  Запрос на подтверждение автоматически аннулируется через 60 секунд.
- С флагом `--force` удаление выполняется немедленно без подтверждения.

**Примеры:**
```text
/delete Марина
/delete Марина --force
```

---

### 2.9 `/status`
Отображает системную статистику: общее число клиентов, количество активных, отключённых и просроченных записей, а также статус фонового обновления базы.

## 3. Настройка белого списка администраторов (Whitelist)

Белый список настраивается в файле конфигурации бота `/etc/sirin/sirinbot.toml`.

Поддерживается как список идентификаторов `telegram_ids`, так и обратная совместимость с одиночным параметром `admin_id`.

```toml
# /etc/sirin/sirinbot.toml

bot_token = YOUR_TELEGRAM_BOT_TOKEN
clients_path = "/etc/sirin/clients.json"

[admin]
# Список Telegram User ID администраторов:
telegram_ids = [
    540209678,
    987654321
]

# Для обратной совместимости (если telegram_ids не задан):
# admin_id = 540209678
```

После редактирования конфигурации перезапустите контейнер:
```bash
docker compose restart sirinbot
```

## 4. Журналирование и аудит действий

Все действия администраторов и попытки несанкционированного доступа логируются в формате structured JSON (`logAdminAction`) в стандартный вывод контейнера `sirinbot`:

```json
{
  "event": "admin_action",
  "admin_id": 540209678,
  "admin_username": "sirin_admin",
  "command": "/extend",
  "target": "11111111-1111-1111-1111-111111111111",
  "details": "extended by 30 days, new expiry: 2026-11-20T12:00:00Z",
  "timestamp": "2026-10-19T23:30:00Z"
}
```

Для просмотра логов в реальном времени:
```bash
docker compose logs -f sirinbot
# Или поиск всех действий администраторов:
docker compose logs sirinbot | grep "admin_action"
```

## 5. Атомарность и целостность данных

- Все операции чтения и записи `clients.json` защищены мьютексом (`sync.RWMutex`) внутри процесса `sirinbot`.
- Запись на диск выполняется атомарно: данные сначала сериализуются во временный файл `clients.json.tmp.<nanos>`, после чего атомарно заменяют целевой файл вызовом системного `rename`. Это исключает повреждение файла при сбоях питания или перезапусках.
- Фоновый процесс демона `sirind` проверяет `clients.json` каждые 30 секунд и автоматически обновляет белый список активных ключей ядра VPN без перезапуска сервера.
