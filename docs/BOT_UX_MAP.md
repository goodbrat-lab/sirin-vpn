# Карта экранов и диалогов Telegram-бота Sirin (BOT_UX_MAP)

В данном документе представлена архитектурная схема экранов, диалогов конечного автомата (FSM) и навигации Telegram-бота `@sirin_crp_bot`.

---

## 1. Схема навигации и иерархия экранов

```text
Главное меню (menu:main)
├── 👥 Клиенты (menu:clients)
│   ├── Список (пагинация по 5 клиентов/стр., статус, дни)
│   │   ├── [◀] [n/total] [▶] (навигация страниц)
│   │   ├── [🔍 Фильтр] → FSM: clients_filter → Список с фильтром
│   │   │   └── [✖️ Сбросить фильтр]
│   │   └── [⬅️ В меню]
│   └── 👤 Карточка клиента (client:view:<uuid>)
│       ├── [👁 Показать UUID] → Сообщение с UUID (автоскрытие через 30с / [🙈 Скрыть])
│       ├── [✏️ Переименовать] → FSM: rename_new → Обновление имени → Карточка
│       ├── [➕ Продлить] → Выбор (+7д, +30д, +90д, +365д или [✏️ Другой срок] FSM: extend_days)
│       ├── [➖ Сократить] → Выбор (-7д, -30д, -90д, -365д или [✏️ Другой срок] FSM: shorten_days)
│       │   └── (Если срок уходит в прошлое) → Предупреждение с подтверждением
│       ├── [🔴 Отключить] / [🟢 Включить] → Мгновенное переключение revoked (soft-delete)
│       ├── [🔄 Узел: <Имя>] → Экран выбора узла (client:choose_relay:<uuid>) → Проверка лимитов → Карточка
│       ├── [🗑 Удалить] → Диалог подтверждения (таймаут 60с) → Удаление
│       ├── [📋 Ссылки] → sirin:// deep-link и веб-ссылка
│       └── [⬅️ К клиентам] / [🏠 В меню]

│   ├── [👥 Клиенты Direct] → Список клиентов на Direct NL (relay:clients:0)

│   │   ├── [👥 Список клиентов] → Список клиентов на релее (relay:clients:<id>)
│   │   ├── [📋 Назначить клиента] → Список доступных клиентов для привязки (relay:assign:<id>)
│   │   ├── [🗑 Удалить релей] → Только при 0 клиентах (relay:delete:<id>)
│   │   └── [⬅️ К релеям] / [🏠 В меню]
│   ├── [➕ Добавить релей] (relay:add) — Мастер FSM из 5 шагов:
│   │   ├── Шаг 1/5: Название (FSM: relay_add_name)
│   │   ├── Шаг 2/5: Host (FSM: relay_add_host)
│   │   ├── Шаг 3/5: Порт VLESS (FSM: relay_add_port_vless, default 443)
│   │   ├── Шаг 4/5: Порт XHTTP (FSM: relay_add_port_xhttp, default 8443)
│   │   ├── Шаг 5/5: Лимит клиентов (FSM: relay_add_max_clients, default 10)
│   │   ├── Подтверждение (relay:add_confirm) → автогенерация ID (max+1) → Карточка релея
│   │   └── [✖️ Отмена] → Экран релеев
│   └── [🏠 В меню]
│
├── ➕ Новый клиент (menu:new) — Мастер FSM из 3 шагов:
│   ├── Шаг 1/3: Ввод имени (FSM: new_name) [✖️ Отмена]
│   ├── Шаг 2/3: Выбор срока (7д, 30д, 90д, 180д, 365д или [✏️ Другой срок] FSM: new_days_custom)
│   │   ├── [⬅️ Назад] → Шаг 1
│   │   └── [✖️ Отмена] → Главное меню
│   ├── Шаг 3/3: Подтверждение создания [✅ Создать]
│   │   ├── [⬅️ Назад] → Шаг 2
│   │   └── [✖️ Отмена] → Главное меню
│   └── Результат создания:
│       ├── Карточка нового ключа с маскированным UUID
│       └── Кнопки: [👁 Показать UUID] | [📋 Ссылки] | [👤 Карточка] | [🏠 В меню]
│
├── 📊 Статистика (menu:stats)
│   ├── Счётчики: всего, активных, истекающих <7д, отключённых, просроченных
│   ├── Новых за 7 и 30 дней
│   ├── [⏳ Истекают <7д] → Быстрый фильтр списка клиентов
│   ├── [🔄 Обновить]
│   └── [🏠 В меню]
│
├── 🔍 Поиск (menu:search)
│   ├── FSM: search_query (ввод имени или префикса UUID ≥6 символов)
│   ├── 0 совпадений → Сообщение об ошибке + [🔍 Искать снова] | [🏠 В меню]
```

## 2. Поведение диалогов и FSM (Finite State Machine)

1. **In-Memory хранение состояний**:
   - Состояния хранятся в оперативной памяти бота (`map[int64]*State`) с защитой `sync.RWMutex`.
   - Время жизни незавершённого состояния (TTL) — **5 минут**.
   - Каждые 60 секунд фоновая горутина очищает устаревшие сессии.

2. **Отмена и сброс**:
   - Нажатие любой команды (`/menu`, `/start`, `/list` и т.д.) немедленно аннулирует текущее FSM-состояние.
   - Во всех диалогах доступна кнопка `[✖️ Отмена]`, возвращающая пользователя в главное меню или карточку клиента.

3. **Редактирование сообщений (EditMessageText) vs Отправка (SendMessage)**:
   - Вся внутренняя навигация по меню и переключение шагов выполняются через `EditMessageText` для предотвращения спама в чате.
   - `SendMessage` (отправка нового сообщения) применяется исключительно для:
     - Карточки только что созданного ключа (чтобы сохранить факт создания в истории);
     - Временного сообщения с полным UUID («Показать UUID»);
     - Ответов на прямые текстовые команды.

4. **Защита от двойных нажатий (Deduplication)**:
   - Все callback-запросы защищены дебаунсом 300 мс, игнорирующим случайные повторные клики.
   - Каждый входящий callback обязательно завершается `answerCallbackQuery` для снятия индикатора загрузки в клиенте.
